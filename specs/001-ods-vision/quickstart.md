# Быстрый старт: проверка MVP портала ODS

Руководство для **ручной приёмки** после реализации по [tasks.md](./tasks.md).  
Контракты: [`contracts/openapi.yaml`](contracts/openapi.yaml), [`contracts/ui-routes.md`](contracts/ui-routes.md).  
Модель данных: [`data-model.md`](data-model.md).

## Предварительные условия

- Docker и Docker Compose
- Git (для проектов с Git URL)
- Тестовый репозиторий с файлами `.md`, `.cs`, `.ts`

## Запуск (после реализации приложения)

```bash
# из корня репозитория приложения ODS (будущий apps/ods-portal)
docker compose up -d
open http://localhost:3000
```

Ожидание: интерфейс и API доступны; **Elasticsearch** (single-node) и том `workspace` созданы.

## Сценарий 1 — Регистрация и дерево (US-1, FR-001)

1. Открыть `/` **без входа** → «Новый проект»: указать Git URL или локальный путь.
2. (По желанию) `/projects/:id/admin` → **Синхронизация** для обновления рабочей копии.
3. Открыть **Дерево** — видны папки и файлы рабочей копии.
4. Элементы имеют статус «найдено автоматически».

**Проверка через API**:

```bash
curl -s http://localhost:8080/api/v1/projects | jq .
curl -X POST http://localhost:8080/api/v1/projects/{id}/sync
curl -s "http://localhost:8080/api/v1/projects/{id}/tree?parentPath=&depth=2" | jq .
```

## Сценарий 2 — Чтение и правка файла (FR-002, FR-003)

1. Открыть существующий текстовый файл из дерева.
2. Изменить содержимое → **Сохранить**.
3. Закрыть и открыть снова — изменения на месте.

**Проверка через API**:

```bash
curl -s "http://localhost:8080/api/v1/projects/{id}/files?path=README.md" | jq .
# PUT с baseContentHash из ответа GET
```

## Сценарий 3 — Создать новый файл (FR-003, T056)

1. Открыть **Дерево** проекта.
2. Нажать **«Новый файл»**, указать путь (например `docs/new-note.md`) и при желании начальный текст.
3. Подтвердить создание — файл появляется в дереве со статусом «найдено автоматически».
4. Открыть созданный файл — содержимое соответствует введённому (или пустое).
5. Повторить создание по **тому же пути** → ожидается ошибка «файл уже существует» (не перезапись без явного редактирования).

**Проверка через API**:

```bash
curl -s -X POST "http://localhost:8080/api/v1/projects/{id}/files" \
  -H "Content-Type: application/json" \
  -d '{"path":"docs/new-note.md","content":"# Заметка\n"}' | jq .

curl -s "http://localhost:8080/api/v1/projects/{id}/files?path=docs/new-note.md" | jq .

# Повторный POST по тому же path — ожидается 409
curl -s -o /dev/null -w "%{http_code}\n" -X POST \
  "http://localhost:8080/api/v1/projects/{id}/files" \
  -H "Content-Type: application/json" \
  -d '{"path":"docs/new-note.md","content":""}'
```

## Сценарий 4 — Конфликт сохранения (FR-011)

1. Открыть файл в UI (запомнить hash).
2. Изменить тот же файл на диске вне UI.
3. Сохранить из UI → ожидается **409** и диалог конфликта.
4. «Отмена» — файл на диске не перезаписан.

## Сценарий 5 — Статусы (US-3, FR-005)

1. Выбрать файл → сменить статус на «нужен».
2. Обновить страницу — статус сохранён.
3. Бейдж / фильтр отображает новое значение.

## Сценарий 6 — Документация и связи (US-2, FR-009, FR-010)

1. Открыть раздел **Документация** — список `.md` / `.adoc`.
2. Из файла кода создать связь с документом.
3. Из файла кода — перейти к связанному документу одним кликом.
4. Контекст проекта не сбрасывается.

## Сценарий 7 — Единый интерфейс (US-2, SC-003)

Цепочка без терминала: проект → файл кода → документ → обратно к дереву.  
Один стиль навигации, один домен приложения.
