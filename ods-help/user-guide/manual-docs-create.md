# Manual: create project docs (from ES via AI)

**Status**: user-facing summary of the agreed `015` vision  
**Source of truth (design)**: `ods-help/requirements/015-project-docs-draft.md`  
**Prompt template**: `prompts/docs-agent-prompt.md`  
**Language**: English  

> This guide describes **what you do** to produce Markdown docs for an analyzed
> project. Feature `015` is still paused in the roadmap — UI labels and exact
> REST paths may change when it ships. Do not invent steps beyond this file
> and the vision draft.

---

## What this is (and is not)

| | |
|---|---|
| **Docs** | Markdown documentation of the **analyzed** system, generated by an AI agent from Elasticsearch data |
| **Specs** | ODS product requirements in `specs/**` — different thing |
| **Who writes docs** | An **external** AI agent (Cursor, Claude Code, …) over ODS REST |
| **What ODS does in MVP** | Keeps the graph in ES, stores `AGENT.md` + docs under `DATA_ROOT/docs/`, lets you **download the prompt**, shows status — it does **not** run the LLM itself |
| **What the agent must not do** | Read the project working copy (WC); mutate the ES graph |

Typical chain: **Import → analyze (parsers) → ES graph ready → download prompt → run external agent → docs appear in Documentation**.

---

## Prerequisites

1. ODS is running (local full stack example API base: `http://localhost:8080/api/v1`).
2. Project is **imported**.
3. A **successful full analysis** exists (current `analysis_run_id`).
4. You have an AI tool that can call HTTP (fetch/curl) and follow a long prompt.

On **import**, ODS already creates:

```text
DATA_ROOT/docs/{projectId}/
  AGENT.md          # seeded project prompt (not a system spec)
```

Opening **Documentation** right after import is normal: the tree may contain
only `AGENT.md` until the agent runs.

---

## Where things live

| What | Where |
|------|--------|
| Product prompt template | Repo: `prompts/docs-agent-prompt.md` |
| Project prompt (rendered) | `DATA_ROOT/docs/{projectId}/AGENT.md` |
| Generated docs | Same folder: `spec-*.md` and optional thematic files |
| Analyzed source (WC) | `DATA_ROOT/working-copies/{projectId}/` — **not** used for docs generation |
| Export pack | **Later** — after docs exist; includes `docs/` (with `AGENT.md`) + `es-data/` |

Docs tree shape (after generation):

```text
docs/{projectId}/
  AGENT.md
  spec-{project-name}.md
  {component}/
    spec-{component}.md
    contracts/ …     # only if ES has data
    messaging/ …
    …
```

Default write mode: **overwrite** the same paths on a new run. Debug-only:
`versioned` writes under `_generations/{id}/` without touching the current tree.

## Steps (user)

### 1. Open Documentation

In the portal: open the project → **Documentation**.

- Left/center: file tree + Markdown viewer (`AGENT.md` first).
- Right properties panel (top → bottom):
  1. **Docs properties** — job status, language, `analysis_run_id`, file counts, summary/gaps when available;
  2. **Language** `en` / `ru` (default = current portal locale);
  3. Button **Download prompt** (always the same label; not renamed to “regenerate”).

The button is enabled after a successful full analysis.

### 2. Choose docs language (optional)

Set `en` or `ru` in the right panel. Default follows the portal locale.
Canonical names/ids from ES stay untranslated; prose follows the chosen language.

### 3. Download prompt

Click **Download prompt**. ODS:

- refreshes `docs/{projectId}/AGENT.md` with current `ODS_BASE_URL`, `PROJECT_ID`,
  `ANALYSIS_RUN_ID`, `DOCS_LANGUAGE`, job id, write mode, …;
- starts/updates AiJob `docs_from_es` (`running`) when applicable;
- downloads `AGENT.md` to your machine.

You do **not** have to re-download every time if the on-disk / in-ODS prompt is
still current. Re-download when URL, analysis, or language changed.

### 4. Run an external agent with `AGENT.md`

Give the agent the prompt and ask it to execute it (example wording:
“Follow AGENT.md and build the docs”).

The agent must be able to reach ODS REST (same machine or reachable host).

#### Option A — Cursor

1. Create/open a folder (can be empty; you do **not** need the analyzed repo).
2. Put `AGENT.md` there (or attach/`@` it in chat).
3. Ask the agent to follow the prompt.
4. Agent reads graph via REST, writes `spec-*.md` into ODS docs, completes the AiJob.

#### Option B — Claude Code in VS Code

Same idea as Cursor: open a folder with `AGENT.md`, run Claude Code, ask it to
follow the prompt. Needs HTTP/tool access to `ODS_BASE_URL`.

#### Option C — Claude Desktop

Needs an MCP wrapper over the same ODS REST APIs (**planned later**, not MVP).
Until MCP exists, prefer Cursor or Claude Code.

### 5. Watch results in ODS

While/after the agent works:

- Documentation tree fills with `spec-*.md` (and optional contract/messaging files);
- right-panel **docs properties** update from AiJob (`running` → `succeeded` / `failed`);
- on **succeeded**: toast that docs are ready; **Export** becomes available when that feature ships (no auto-open of the export dialog).

The agent reports completion only to the **backend** (AiJob API). It does not call the portal UI directly.

### 6. Export (later)

When export exists and the docs job has succeeded, the **Export** button in
the Documentation right panel becomes available. ODS backend builds and
downloads one file:

```text
export-{projectId}-{timestamp}.zip
```

The ZIP contains at least:

- `docs/` including `AGENT.md` (provenance: which prompt built these docs);
- `es-data/` slice for the project;
- `manifest.json` and a README documenting the recipient's `BASE_ES_URL` for
  post-export ES links.

Give this ZIP to another person or move it to another computer for review,
analysis, or as input to a separate attempt to build a new system. ODS creates
the export pack; rebuilding a target system is **outside ODS**, and exact source
reconstruction is not guaranteed.

## What the agent does (short)

1. Talks only to ODS REST (ES-backed project/analysis/graph data).
2. Does **not** read WC source files.
3. Writes Markdown under `docs/{projectId}/` only; **must not** overwrite `AGENT.md`.
4. Puts `project_id`, `analysis_run_id`, `docs_language`, and ES refs (index/id + visible Fetch URL) into docs.
5. Marks missing data as `GAP` / `UNKNOWN` — does not invent APIs or components.
6. Ends with AiJob `succeeded` or `failed` + short summary.

## Quick checklist

- [ ] ODS up; project imported; analysis succeeded  
- [ ] Documentation open; language set if needed  
- [ ] **Download prompt** → got `AGENT.md`  
- [ ] External agent (Cursor / Claude Code / …) can reach `ODS_BASE_URL`  
- [ ] Agent finished; tree + properties show docs; job `succeeded`  
- [ ] (Later) Export one ZIP if you need to review or use docs + ES data elsewhere
