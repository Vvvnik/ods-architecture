# Черновик: 007-portal-scale-ux

> **Статус:** черновик для `/speckit-specify` → `specs/007-portal-scale-ux/`
> **Зависимости:** `003-portal-mvp`, `006-project-graph` (реализованы)
> **Не входит:** редактирование графа, canvas, Graphify (→ `008`)

## Цель

Масштабирование портала для больших проектов: удобная вёрстка workspace, **каскад статусов
папок** в дереве файлов и навигация по тысячам узлов канонического графа (`006`)
**без** графической схемы (React Flow — позже).

## User stories (черновик)

### US1 — Регулируемая ширина панелей workspace

- Три колонки (`003`): дерево / просмотр файла / свойства.
- Перетаскивание разделителей; сохранение ширин в `localStorage` (опционально).
- Минимальные ширины, чтобы «Свойства» не сжимались до нечитаемости.

### US2 — Иерархия узлов графа с lazy load

- На `/graph` — дерево по `parent_id` / `qualified_name`, свёрнуто на верхнем уровне.
- Раскрытие узла → подгрузка детей (API + пагинация).
- Альтернатива плоскому списку 50+offset для больших проектов.

**Backend (черновик):** `GET .../graph/nodes?parent_id=...&limit&offset` или эквивалент.

### US3 — Поиск по Elasticsearch (узлы и рёбра)

- Поле ввода + кнопка «Найти» на `/graph` (или отдельная панель поиска).
- Поиск по канону `006`: узлы (`name`, `path`, `kind`, `qualified_name`) и рёбра (`type`, `from`, `to`).
- Результаты: две вкладки или секции «Узлы» / «Рёбра»; клик → выбор в списке / переход к рёбрам.
- Пагинация результатов; лимит на запрос.

**Backend (черновик):** `GET .../graph/search?q=...&scope=nodes|edges|both&limit&offset`.

### US4 — Каскад статуса папки в дереве файлов

**Проблема сейчас:** при смене статуса **папки** на `not_needed` («Не нужен») файлы и
вложенные папки внутри остаются `auto_found` («Найдено автоматически») — статус
меняется только у одного элемента (`002`/`003`, без каскада).

**Ожидаемое поведение:**

1. **PATCH статуса папки (`directory`)** → каскад **вниз** на все активные потомки
   (`path` с префиксом `папка/`): те же `status` и `status_manually_set: true`.
2. Папка → **`not_needed`**: все файлы и подпапки внутри (рекурсивно) → `not_needed`.
3. Папка → **`needed`** (и при необходимости другие статусы по согласованию в спеке):
   симметричный каскад вниз — чтобы не оставались «авто» внутри явно помеченной ветки.
4. **Sync:** новый или обновлённый элемент под предком с `not_needed` +
   `status_manually_set` → получает `not_needed` (наследование по цепочке `parent_path`),
   пока у него нет собственной ручной пометки.

**Границы и конфликты (зафиксировать в spec):**

| Ситуация | Решение (черновик) |
|----------|-------------------|
| Родитель → `not_needed`, у ребёнка был вручную `needed` | Побеждает **родитель** (действие на ветке) |
| Родитель поднят из `not_needed` в `needed` / `auto_found` | Дети **не** меняются автоматически (не затирать ручные пометки внутри) |
| Смена статуса **файла** (лист) | Только этот элемент, без каскада |
| Старые проекты в ES | Миграция не обязательна; каскад срабатывает при следующем PATCH/sync |

**Backend (черновик):** расширить `PATCH .../elements/:id` — при `type=directory` bulk-update
потомков в ES; в `sync.service` — `resolveStatusOnSync` с учётом предков.

**Связь с графом (post-MVP):** фильтр «не показывать `not_needed`» опирается на статус
элемента дерева по `path`; каскад папки делает поведение предсказуемым без правки каждого файла.

> Спеки `002`/`003` **не меняем** в этом черновике; поведение описывается и реализуется в рамках `007`.

## Post-MVP (не 007) — скрытие в графе по статусу

Идея: элементы с `not_needed` не показывать в визуализации графа (фильтр по `path` / статусу дерева).
Каскад папки (US4) готовит данные; **редактирование узлов графа** в UI — не входит.
Политика при повторном sync/анализе (восстановление узла из кода) — **отложена**.
См. `specs/001-ods-vision/spec.md` §Post-MVP backlog.
