# Главное простыми словами

## Резюме

1. CRITICAL (C1) — блокер
Spec всё ещё «Черновик», а по конституции проекта перед кодом нужно согласование spec + plan + tasks.
→ Formal «можно писать код» пока нет.

2. HIGH (I1) — важное расхождение
В plan/tasks — только Elasticsearch.
В spec (Assumptions) — ещё фигурирует PostgreSQL.
→ Нужно подтянуть spec под ES (версия 1.3.0).

3. HIGH (I2) — формулировка
В FR-001 — «администратор» регистрирует проект, но входа в MVP нет → по факту любой может всё делать.
→ Уточнить в spec: «страница /admin, без ролей в MVP».

4. MEDIUM (U1–U4) — мелкие дыры в tasks
Не хватает явных задач на: создание нового файла, ошибку кодировки, UI при сбое sync, оглавление/фильтр статусов.
→ Добавить 4–6 задач в tasks.md (можно перед или во время implement).

5. Остальное — OK
55 задач в целом покрывают MVP (FR-001–011). Post-MVP (граф) — правильно без задач.
